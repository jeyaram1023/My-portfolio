02 · Threat Model

Wireless exposure is a structural flaw.

Nearly every proposed improvement in access-control secures a wireless channel rather than removing it. The attack surface is the radio link itself.

A relay attack doesn't need to break AES. It only needs two radios bridging the distance between a key on a kitchen counter and a vehicle parked on the street.

WireLock's premise is structural: if the KEY physically cannot transmit over the air, there is no signal left to relay, replay, amplify, or clone.

RELAY ATTACKS [MITIGATED]
Zero antennas mean amplifiers cannot bridge physical distance to the KEY.
REPLAY ATTACKS [MITIGATED]
Captured payloads are invalidated by a strict rolling 16-byte TRNG nonce.
RFID CLONING [MITIGATED]
Static UIDs are wrapped in AES-256-CBC and permuted dynamically.

04 · Cryptographic Stack

Five layers of security.

Every insertion runs the full stack sequentially — providing hardware proof-of-presence, ephemeral challenges, encryption, and mutation.

Zero-Trust Provisioning

Before pairing, the Master polls the KEY's EEPROM. A new AES-256 key is only written if every byte strictly reads 0xFF — proof of a physical factory reset.

The AES key crosses the wire exactly once during setup, and never again.

> poll(EEPROM)
> read: 0xFF 0xFF 0xFF 0xFF …
> state: FACTORY-RESET CONFIRMED
> write(AES_256_KEY) → KEY
ASCON-128 Ephemeral Handshake

On insertion, the Master issues a 16-byte TRNG nonce. Both sides compute a 16-byte MAC using the lightweight ASCON-128 AEAD algorithm.

AES-256-CBC Encryption

The Master reads a 16-byte IV and a 20-byte encrypted payload. Every session gets a brand-new cryptographically random IV.

> IV = TRNG(16B)  // fresh session
> payload = UID ‖ C_n  (20B)
> ct = AES256_CBC_encrypt(payload, IV)
Dynamic Permutation

The ciphertext is split into five blocks. The transmit sequence is derived from the session counter: I_seq = C_n mod 120.

> blocks = [b0 b1 b2 b3 b4]
> I_seq = C_n mod 120
> order = LUT[I_seq]
> tx: b3 → b0 → b1 → b4 → b2
Tearing Mitigation

If power is lost mid-write, WireLock detects the previous state `n-1` on next boot and silently rolls forward, preventing locked out KEYs.

> expected: C_n
> received: C_n₋₁  // power loss
> window check: PASS (n−1)
